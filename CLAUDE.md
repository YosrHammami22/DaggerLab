# DaggerLab — rules for Claude

## Project
Android app in Kotlin, Jetpack Compose, Dagger 2 (no Hilt), KSP, Room, Coroutines/Flow.
Single module `:app`, package `com.yosrhammami.daggerlab`. Versions in `gradle/libs.versions.toml`.
Feature: a sleep timer (15/30/60 min) that remembers the last chosen duration in Room.

## Commands
- Build: `./gradlew :app:assembleDebug`
- Unit tests: `./gradlew :app:testDebugUnitTest`
- Single test class: `./gradlew :app:testDebugUnitTest --tests "com.yosrhammami.daggerlab.ui.player.PlayerViewModelTest"`
- Single test method: add `.methodName` or a wildcard, e.g. `--tests "*PlayerViewModelTest.lastDuration*"`
- Install on device: `./gradlew :app:installDebug`

## Architecture (Clean Architecture, follow it strictly)
- `domain/` : interfaces and business logic. No Android or Room imports.
- `data/` : implementations (Room entities, DAO, repositories).
- `ui/` : ViewModels and Compose screens. No business logic in composables.
- `di/` : all Dagger wiring.
- `util/` : small injectable helpers (`TimeFormatter`, `AppInfoProvider`).

### Dagger graph
- `AppComponent` (`@Singleton`, built in `DaggerLabApplication`, `Context` via `@BindsInstance`)
  includes `DatabaseModule`, `RepositoryModule`, `ViewModelModule`.
- `PlayerSubcomponent` (`@ActivityScope`, `Activity` via `@BindsInstance`) is created in
  `MainActivity.onCreate` **before** `super.onCreate()` and injects `ViewModelFactory`.
- ViewModels come from `ViewModelFactory` (multibound `Map<Class<out ViewModel>, Provider<ViewModel>>`):
  `viewModel(factory = viewModelFactory)`. A VM missing from `ViewModelModule` compiles fine but
  **crashes at runtime**, so always register it.
- `DaggerAppComponent` is generated by KSP; a missing binding fails the build.

### UI pattern
- Screen state is a sealed interface (`ui/screen/SleepTimerUiState`: Idle / Running / Finished).
- ViewModel exposes `uiState: StateFlow<...>` (built with `combine` + `stateIn(WhileSubscribed(5_000))`)
  and `onXxxClick` event functions.
- `MainScreen` collects with `collectAsStateWithLifecycle()` and dispatches to stateless
  `*Content` composables that take values + callbacks (each has a `@Preview`). Text comes from `strings.xml`.

### Room
- Schema exported to `app/schemas/` (KSP arg `room.schemaLocation`). Changing an entity requires
  bumping `AppDatabase.version` and providing a migration.

## Dagger patterns to reuse
- Interface → implementation: `@Binds` in `RepositoryModule` (see existing examples).
- Third-party types (Room): `@Provides` in `DatabaseModule`.
- New ViewModel: `@Inject constructor` + `@Binds @IntoMap @ViewModelKey` in `ViewModelModule`.
- Never inject an Activity-scoped object into a ViewModel.

## Testing
- Unit tests only (`app/src/test`); ViewModels are constructed directly, without Dagger.
- `MainDispatcherRule` (test root package) uses `StandardTestDispatcher`: coroutines don't run until you
  call `advanceTimeBy` / `advanceUntilIdle` / `runCurrent` inside `runTest`.
- Hand-written fakes live in the `fake/` test package (e.g. `FakeSleepTimerSettingsRepository`).

## Rules
- Do NOT add any new library or Gradle dependency.
- Reuse existing code before creating new classes (`TimeFormatter`, repositories, fakes).
- Every new logic class gets unit tests, in the style of `PlayerViewModelTest`:
  `MainDispatcherRule`, Turbine, hand-written fakes (no mocking library).
- Test packages mirror main source packages.
- Work step by step: do ONE step, show the changes, then STOP and wait for my approval.
- NEVER run `git commit` or `git push`. I commit myself.
